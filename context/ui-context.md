# UI Context

## Product character

The customer-facing experience should feel trustworthy, modern, simple, and professional. It should help a customer complete feedback in a few clear steps without pressure or dark patterns.

## Responsive strategy

- Mobile-first.
- Comfortable touch targets.
- Responsive layouts for tablet and desktop.
- Avoid dense dashboards in the public customer flow.

## Core customer UI

The initial customer experience should support:

- Client/business identity.
- Service selection using clear selectable cards or controls.
- Accessible 1–5 star rating.
- Optional written feedback textarea.
- Clear submit action.
- Review draft presented as editable text.
- Copy action with clear feedback about success.
- Explicit user-controlled transition toward public review publishing.

## Accessibility

- Use semantic HTML and accessible labels.
- Keyboard navigation must work.
- Star rating must have a non-visual accessible representation.
- Do not rely on color alone to communicate state.
- Maintain readable contrast and visible focus states.
- Error and success states must be understandable without animation.

## Visual system

Exact colors, typography, component library, icon set, spacing scale, and brand assets are TBD until the implementation stack and RM Solution brand direction are explicitly selected.

Do not invent a complete design system in a feature spec. Record global visual decisions here once approved.

## UX principles

- One clear primary action per step.
- Explain why information is requested when it is not obvious.
- Preserve user-entered text.
- Never disguise AI-generated content as a verbatim customer statement.
- Never use manipulative language to push a positive review.
- Loading, empty, error, and success states are part of the design, not afterthoughts.
